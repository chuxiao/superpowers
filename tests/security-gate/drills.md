# 安全门 drill 场景规格

真实会话验证安全门行为的场景定义。静态断言（test-security-gate.sh）证明结构与对齐存在；本文件的场景证明行为发生。执行记录见文末（Task 6）。

## 场景

### ① 触发路径：预埋数据流缺陷

- 前置：临时 worktree 中构造一个分支，含一个最小脚本文件——环境变量的值未经校验拼接进 shell 命令执行（如 `sh -c "grep $USER_INPUT data.txt"`，USER_INPUT 来自脚本参数）。
- 执行：按挂载段规则对该分支派发真实安全审查者子代理（security-reviewer.md 模板，输入 = 审查包 + 空终审发现清单 + 台账指引）。
- 期望（可判真伪）：报告含至少一条 Critical 级发现项；该发现项含四要素（位置/缺陷/可被利用路径/修复方向）；Verdict 不是 Clean-Pass。随后派单个修复者修复 → 安全复审 → 全部 ADDRESSED，全程恰好一轮。

### ② 放行路径：纯文档/测试改动

- 前置：一个只含文档与测试文件改动的分支（无源代码改动）。
- 执行：按挂载段规则派发真实安全审查者子代理。
- 期望（可判真伪）：Verdict 为 Clean-Pass；依据恰为一句，写明五面均未触及。

### ③ 召回路径：隐蔽变体（留 eval 仓库执行）

- 前置：缺陷与场景①同构但表述隐蔽——外部输入经中间变量、默认值或间接展开到达危险汇（不出现显眼的拼接形式）。
- 执行：同①。
- 期望（可判真伪）：安全门必须报 Critical；放行即本场景 FAIL。本场景检验判据的召回率下限，与①的差异仅在缺陷隐蔽度。

### ④ 残留移交：修复不完整（留 eval 仓库执行）

- 前置：同①，但修复轮只修复部分发现项。
- 执行：安全门 → 修复 → 安全复审。
- 期望（可判真伪）：复审报告含 NOT ADDRESSED 判定；全程恰好一轮，无第二轮；残留项以 `Final: security-gate:` 行进台账并出现在最终消息 Security gate 小节。注：不在正常会话中诱导真实子代理做不完整修复，故留 eval 仓库以受控审查者执行。

## 落地说明

- 场景①②由实施会话执行（本文件文末执行记录）；场景③④留外部 eval 仓库（superpowers-evals）以受控审查者批量执行——③检验召回、④检验熔断与移交，两者需要可编程的受控审查者，正常会话不具备该条件。
- 预埋缺陷代码只存在于临时 worktree，不提交到任何共享分支；执行后 worktree 即删。
- 设计文档合入门（§5：新机制不带 drill 证据不得合入）由场景①②的执行记录满足。
