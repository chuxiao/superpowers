# 设计文档：废除小改动豁免，全量改动统一完整工作流

> 读者假设：懂软件工程，不熟悉产生本文档的对话；不需要了解本仓库技能文本的内部结构。
>
> 本文档回答：做什么、不做什么、为什么这样取舍、成本量级与主要风险。实现细节留给计划。

4. 完整五章覆盖软件内外；非软件项目维持设计确认后即止、不调用计划技能的既有停止点——需求方裁决（2026-11-03，随设计确认一并拍板）。

6. 技能文本验证方式（审读 A5，2026-11-03 裁决）：行为证据（压力场景对照）+ 机械断言，不另设文档式审读。

## 1. 背景与目标

解决什么问题：现行工作流给小改动留了三条豁免路径，任何一条被走通，这次改动就不留记录、或只留残缺记录：

- 需求描述完备时，agent 可判定任务「快速、清晰」后直接实现，不出任何文档。
- 需求方判级为「小改动」后，设计文档写简短版，不做独立审读、不进入计划流程——没有计划文档，也没有验证方案。
- 需求方选择退出提问后，技能即告完成、闸门解除，可以直接构建。

记录残缺的直接后果：验证方案不并入登记册，集成验证与全量回归覆盖不到这次改动；日后审计找不到这次改动为什么这样做。

给谁用：最终用户是执行工作流的 agent。

成功判断标准：

- 需求方只读工作流技能文本，找不到任何按规模或按意愿豁免流程环节的出口。
- 集成验证的机械断言能验证豁免表述清零、新纪律句在场。

## 2. 功能清单

### 卡片 1：废除小改动豁免

1. **定位：** 小改动简短版豁免整体废除，所有软件改动统一产出完整设计文档。
2. **触发与输入：** 工作流技能进行到设计文档环节；输入为对话中确认的需求与需求方拍板的方案。
3. **执行要点：**
   - 工作流技能正文不再含任何按规模豁免流程环节的表述：规模对照表、判级规则、简短版格式、判错升级，全部移除。
   - 正文流程步骤中的「简短版或完整版」措辞收敛为完整设计文档，指向规模对照节的引用同步清除；随规模对照节失效的「规模上调」句一并移除；指向模板的引用句中「小改动规则」字样同步清除。
   - 设计文档模板不再含简短版一节。
   - 任何改动的设计文档一律五章，含文首固定块与审读处置附录。
   - 非软件项目（演讲、生意、装修类）同样适用完整五章；维持设计确认后即止、不调用计划技能的既有停止点（需求方裁决 2026-11-03）。
4. **出口表：** 单一出口——所有改动进入完整流程，一行文字即可。
5. **流程图：** 不配。卡片无决策分支、无多出口。
6. **本次不做：** 执行方式选择的规模口径（§3 第 4 条「计划批准后的执行方式不动」）。

最终用户看到什么：执行 agent 在任何改动上得到同一套文档要求；审计者读到格式一致、环节齐全的记录。

### 卡片 2：「直接做」改为跳过对话不跳流程

1. **定位：** 需求描述完备不再触发直接实现，改为省略提问、直接进入方案与文档流程。
2. **触发与输入：** 技能首次分类时判定需求描述已完备；或需求方在对话中要求「直接开干」。
3. **执行要点：**
   - 需求完备时省略提问对话；方案拍板、设计文档、独立审读、需求方确认、实施计划逐环节照走，无一省略。
   - 需求方要求直接开干时，执行 agent 明示：跳过的是对话，不是流程；随后立即进入方案与文档环节。
4. **出口表：** 单一出口——进入方案与文档流程。
5. **流程图：** 不配。卡片无决策分支、无多出口。
6. **本次不做：** spike 例外（§3 第 2 条「spike 用完即弃故保留」）。

最终用户看到什么：即使一句话需求，agent 也交出方案拍板点、设计文档、审读处置与计划确认点。

### 卡片 3：退出提问不再解除闸门

1. **定位：** 需求方退出提问只缩短对话，不再构成对闸门的豁免。
2. **触发与输入：** 需求方在对话中表示不想继续回答问题。
3. **执行要点：**
   - 「退出提问 → 技能完成 → 闸门解除」的例外删除。
   - 闸门的例外仅剩需求方同意的 spike。
   - 技能文本不再提供、也不再提议任何跳过文档与计划的出口。
   - 需求方退出提问后，agent 以已知信息直接进入方案列举与设计文档撰写，闸门照常把守确认环节。
4. **出口表：** 单一出口——闸门保持，流程继续。
5. **流程图：** 不配。卡片无决策分支、无多出口。
6. **本次不做：** 引导技能的全局「用户指令优先」原则（§3 第 3 条「全局规则不属本技能出口」）。

最终用户看到什么：需求方叫停提问后收到的是方案与文档，而不是再次提议直接开工；第一条消息里的既有提议保留，其接受后果是进入方案与文档流程（见卡片 2）。

### 卡片 4：口径同步与机械断言

1. **定位：** 两份面向人的导览文档口径同步，集成验证新增豁免清零断言。
2. **触发与输入：** 本次改动实施时；输入为卡片 1-3 落定后的技能文本。
3. **执行要点：**
   - 项目自述文档中「小改动在对话里敲定」的表述改为：所有需求类改动都产出设计文档与实施计划，流程不因改动小而省略；缺陷修复走修复分支与集成验证门槛（见 §3 第 1 条）。
   - 技能地图中「小改动止于聊天内确认」的表述改为需求类改动三件套口径：需求（feature）类软件改动产出三件套，无规模豁免；缺陷修复走 bugfix 路径（合并前过收官把关与集成验证门槛）；非软件项目止于设计文档。
   - 集成验证测试新增组合断言：设计文档模板按词缺席（「小改动」「简短版」不得出现）；工作流技能正文按短语缺席（简短版、不做独立审读、不进入完整计划流程、判错则升级、这项技能即告完成、也随之解除）；新纪律句在场（措辞见 §4 留给构建者的部分）。
   - 结构检查脚本内引用简短版豁免的过时注释随动更新。
4. **出口表：** 单一出口——断言通过、口径一致。
5. **流程图：** 不配。卡片无决策分支、无多出口。
6. **本次不做：** 既有断言的改动（核对结论见 §5「断言锚点」；锚点字符串须在改写中存活，否则由计划同步修订）。

最终用户看到什么：需求方在导览文档读到与技能一致的口径；集成验证以机械断言守住豁免清零，防止回潮。

## 3. 明确不做

1. 因为改动二分是 2026-11-03 需求方裁决（收尾技能的在册断言可查），且缺陷修复合并前强制过集成验证门槛、合并后的代码被全项目级登记册套件整体覆盖，所以 bugfix 路径不动——把 bugfix 一并纳入需求三件套属另案裁决，不在本次问题范围内。
2. 因为 spike 用完即弃、不产分支、不入登记册，不构成记录盲区，所以保留其闸门例外——这是 2026-10-31 以来记录在案的裁决。
3. 因为「用户指令优先」属于引导技能的全局规则，不是工作流技能自设的出口，所以本次不动它——本次问题局限于工作流技能自身提供的豁免路径。
4. 因为计划批准后的执行方式选择不豁免任何文档或验证环节，所以不动它的规模口径。
5. 因为执行类技能与收尾技能位于计划确认之后，入口输入是已获批的计划或已验证的分支，而本次移除的豁免全部发生在计划确认之前，所以不动它们。

## 4. 关键决策记录

| 决策 | 一句话结论 | 拍板状态 | 影响功能项 |
|------|-----------|---------|-----------|
| D1 文档格式 | 一律完整五章，废除判级 | 已拍板（2026-11-03） | 卡片 1 |
| D2 直接做路径 | 跳过对话，不跳流程 | 已拍板（2026-11-03） | 卡片 2 |
| D3 退出提问与闸门 | 退出提问只缩短对话，不解闸门 | 已拍板（2026-11-03，备注确立） | 卡片 3 |
| D4 断言形式 | 组合断言：模板词缺席 + 正文短语缺席 + 纪律句在场 | 构建者定稿（审读修订为组合式），随计划确认 | 卡片 4 |

**D1 文档格式。**

1. 候选方案：A 一律完整五章；B 保留简短版格式，但审读、确认、计划等流程环节补全。
2. 选了哪个：A。
3. 依据：需求方明确拍板。判级本身是审计口径的弱点——判级是主观判定，「判错升级为项目级」是事后补救，判错的这段时间里记录是残缺的；一律完整五章消除判级，审计口径彻底统一。
4. 代价与风险：琐碎改动（如换一个图标颜色）也写完整五章，文档负担最重。需求方明示接受：记录与审计优先于单次成本。成本量级：琐碎改动的文档环节从几句话升到完整五章加审读加计划，主要成本在审读派发与计划撰写。

**D2 直接做路径。**

1. 候选方案：A 跳过对话不跳流程；B 删除该判定，一切改动先经提问、复述、拍板。
2. 选了哪个：A。
3. 依据：需求完备时提问没有信息增益，完整流程的价值在记录；B 对琐碎改动徒增纯对话开销。选 A 后「直接开干」的语义收敛为「跳过对话」，与 D3 一致。
4. 代价与风险：需求方说「直接开干」时的期待与流程之间有一次说明成本：agent 必须明示跳的是对话、不是流程，可能被需求方再次催促。风险可接受，因为说明只需一句。

**D3 退出提问与闸门。**

1. 候选方案：A 保留退出条款、改写语义为仅缩短对话；B 整段删除退出条款。
2. 选了哪个：A。
3. 依据：需求方备注确立——「流程一定是要照走的，没有需求方明确要求豁免，主要是我要保证验证方案正确并入登记册，保证集成验证和全量回归」。退出提问若解除闸门，登记册就存在盲区。保留条款、收窄语义，比删除更能保住「需求方可以叫停提问」这一正当出口。
4. 代价与风险：spike 之外的任何提前构建都被闸门拦截，无例外；若需求方坚持放弃自己的记录，agent 在对话中留一句书面说明——本设计不为此设出口。成本量级：本决策不新增环节，其开销与 D1 合并计（每改动固定多出审读派发与一份计划），无独立新增成本来源。

**D4 断言形式。**

1. 候选方案：A 在两个断言文件内按词缺席（「小改动」一律不得出现）；B 短语级缺席加新纪律句在场；C 组合——模板按词缺席、正文按短语缺席加纪律句在场。
2. 选了哪个：C（审读后由 B 修订而来）。
3. 依据：设计文档模板内「小改动」只承载豁免语义，删除豁免节后按词缺席无误伤对象，且比短语清单更能防新措辞漏检；工作流技能正文的危险信号表需要逐字引用需求方的合理化借口（既有防堵机制），该词在正文有合法未来用途，按词缺席会迫使合理化借口改写措辞、削弱防堵，故正文退一档用短语清单。
4. 代价与风险：正文的新豁免措辞不落在既有短语清单里，断言拦不住——由独立审读与实施阶段的压力测试兜底，断言只防回潮，不防新漏。成本量级：断言为既有测试文件内追加数行机械检查，边际成本可忽略；主要成本来源是短语清单随豁免措辞演化的维护。

#### 留给构建者的部分

- 「几个相互独立的项目、一次只对一个进行头脑风暴」这条既有规则在规模对照节拆除后的落点（并入对话节，还是保留一个瘦身节），由执行者按技能行文密度决定；规则本身必须保留。为什么交给执行者：落点只影响行文密度，不影响行为。
- 新纪律句的措辞与落点由执行者定；边界：必须可被机械检索命中，命题限于「所有改动一律完整五章」「跳过对话不跳流程」「退出提问不解除闸门」三条之一或多个。为什么交给执行者：断言需要稳定锚点，具体行文属行文密度问题，设计期固定反而易碎。
- 第一条消息里主动提出「直接开工」的既有提议保留，语义按 D2 收窄、与 D3 同向（接受提议 = 跳过对话、进入方案与文档流程），措辞由执行者定。为什么交给执行者：该提议是需求方叫停提问的正当出口，删除它会堵死 D2/D3 要保住的路径。
- 断言在集成验证测试中的插入位置与编号，随测试文件现状定。为什么交给执行者：插入点与编号依附测试文件现行布局，设计期固定易碎。
- 两份导览文档的具体改写措辞，在原句基础上最小改写，不改文档结构。为什么交给执行者：导览文档结构不在本次问题范围内，最小改写可控。

## 5. 关键约束与可行性风险

- 既有集成验证断言已字节级逐条核对：压在工作流技能上的断言共三条，锚定四个字符串——「归档后冻结零改动」（两条断言重复锚定）、「不回写已归档文档」、「收到新问题时先分类」、「bugfix 路径」。前两个不在本次改写区域；后两个位于卡片 2 的分类节改写区域，改写须原样保住锚点字符串，保不住则由计划同步修订该断言——二选一，由计划登记。
- 本次修改的是行为塑形内容：改写后的技能文本以行为证据（压力场景对照）与机械断言验证，不另设文档式审读；实施阶段按技能编写纪律安排压力场景对照（旧文本基线对新文本，压力源为需求方催促「别问了，直接开干」），未见到行为证据不得收尾。
- 影响面已穷举：豁免表述的全仓库引用共五处——工作流技能正文、设计文档模板、结构检查脚本注释、项目自述文档、技能地图——全部登记在功能清单与后续计划中。
- 审读子代理与压力测试都需要子代理工具；无子代理工具的环境按技能既有的自审兜底执行并明示。
