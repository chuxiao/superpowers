# 设计文档模板可读性槽位 — 验证过程记录（2026-11-03）

> 被测对象：`skills/brainstorming/references/design-doc-template.md` 的新旧两版。
> 新版相对旧版增两处槽位：功能清单六字段卡片（定位/触发与输入/执行要点/出口表/流程图/本次不做）与 §4 决策速览表；flowcharts 规则增节点文本预算与一图一主题。
> 本记录回答四个问题：测试用例依据什么生成、测的是什么点、输入是什么、断言是什么——并给出结果与诚实边界。

## 1. 测试用例的生成依据

测试用例（任务提示词）不是随手编的，由四个来源共同决定：

**来源一：真实失效。** 被修的缺陷就是当前模板的真实产出——本仓库 2026-11-01 设计文档与 2026-11-02 实施计划（旧模板产物）出现功能清单大段文本（单条 500 字）、计划任务无流程图、11 个决策无导览。测试任务必须有可能复现同类失效：故选了一个含多功能、多出口、多决策的功能需求，而非单功能小改（单功能会触发「小改动简短版」豁免，测不到卡片槽位）。

**来源二：writing-skills 的失败类型匹配表。** 该表断言：失败类型是「产出形状不对」时，修法是结构槽位，验证手段是对照实验（有无指导两组分布是否分离）。本测据此定为 A/B 两组对照，而非单纯跑新模板看顺不顺眼。

**来源三：微测纪律。** 每臂 ≥5 次重复（单样本会撒谎）、全新上下文逐样本独立（模拟未来真实会话）、人工读每一份产出（自动统计会把回声式输出误判为命中）、方差本身是指标（指导起作用时各次收敛到同一形状；五种解读说明措辞没绑住）。

**来源四：判别点预埋。** 任务需求里刻意放了三个可数的结构，让「槽位是否生效」有客观核对点，而不是靠审阅者印象：

| 预埋点 | 数值 | 用于核对哪个槽位 |
|--------|------|-----------------|
| 功能数 | 2 个 | 卡片结构（1 个功能测不出「逐项同形」） |
| 功能一的结局 | 3 种（前置失败即停 / 部分失败带报告非零 / 全部成功） | 出口表枚举完整性 |
| 团队分歧 | 2 处（部分失败是否回滚、解析器复用方式） | 决策速览表触发条件（≥2 个决策即应出表） |

## 2. 测试点

| # | 测试点 | 守护的失效 | 判定方法 |
|---|--------|-----------|---------|
| 1 | 功能卡片六字段齐全且五份同形 | 功能清单大段文本、各次产出形状漂移 | 机械（闸门脚本字段断言）+ 形状一致性人工比对 |
| 2 | 专用出口表（出口/条件/去向） | 出口信息散落散文、无法扫读 | 机械（表头与行结构） |
| 3 | 决策速览表（≥2 决策时） | 决策多而无导览，读者逐段翻 | 机械（表头含「一句话结论」） |
| 4 | 一张图一个主题 | 链路总览与单环节细节塞进同一张图 | 人工（图的边界划分无机械判据） |
| 5 | mermaid 节点文本 ≤3 行 | 5 行文本节点（真实失效：原流程图 H 节点） | 机械（`<br/>` 计数） |
| 6 | 出口枚举完整性（3 个预埋结局一个不漏） | 出口表漏行（重生成时实际犯过） | 人工对照预埋点逐份清点 |
| 7 | 内容质量不退化（阴性对照点） | 槽位模板把写作变成填表、牺牲论证质量 | 人工读决策论证与「明确不做」因果 |

测试点 1-3、5 是新槽位的直接存在性检查；4、6 是槽位管不到、预期由审读层兜底的类——测它们是为了确认模板改动**没有**把完整性变差；7 是阴性对照——确认形状收益不以内容为代价。

## 3. 输入

**自变量（唯一差异）**：设计文档模板全文。

- 实验组：新版模板，即工作区文件 `skills/brainstorming/references/design-doc-template.md`（已随 8646870 提交）。
- 对照组：旧版模板，取法 `git show 8646870^:skills/brainstorming/references/design-doc-template.md`。

**公共输入（两臂逐字相同）**：框架句 + 任务需求。框架句为「你是一名软件设计代理。请严格按照下面的设计文档模板，为文末需求撰写一份完整的设计文档。只输出文档全文（Markdown），不要调用任何工具，不要输出任何文档之外的解释或说明。」任务需求全文：

> 我们的命令行工具 supercheck 计划新增两个功能，需要一份设计文档供需求方确认取舍。
>
> 功能一：批量导入测试用例。用户指定一个目录，工具读取目录中全部 YAML 用例文件并注册。行为要求：目录不存在或目录中无合法用例文件时，报错退出、不注册任何用例；部分文件解析失败时，注册解析成功的用例、把失败文件逐个列入结果报告、退出码非零；全部成功时注册并输出用例清单。导入过程不得修改已注册的既有用例。团队对「部分文件失败时是否回滚本次已注册的用例」存在分歧，需要在文档中做出取舍论证。
>
> 功能二：supercheck validate 子命令。只校验不注册，对每个用例文件输出合法/非法结论，供 CI 在合并前使用。
>
> 项目形态：纯后端 CLI 工具，无外部接口；实现上可拆为用例解析器与注册表两个模块，两个功能都会用到解析器。

**采样协议**：10 个全新上下文子代理（实验组 5 + 对照组 5），一次性产出、不调用工具、无会话历史；首个发送波撞本机并发限流（429），3 个对照组样本按完成通知分波补位，全部 10 份实际回收。

**控制变量**：两臂除模板全文外无任何差异——同一框架句、同一需求文本、同型子代理、同期运行。模型家族单一（本机默认模型），这是边界不是优点，见 §7。

## 4. 断言

**机械断言**（由 `skills/writing-plans/scripts/check-doc-structure.sh` 承载，即本次同步落地的结构闸门——评分器与闸门是同一个脚本，保证「测的」与「以后拦的」一致）：

| 断言 | 判定规则 |
|------|---------|
| 卡片字段 | 每个 `### 功能` 小节内（剥离加粗标记后）依次含「定位：」「触发与输入」「执行要点」「本次不做」 |
| 决策速览表 | `### 决策` 小节 ≥2 时，存在含「一句话结论」的表格行 |
| Task 职责句 | 每个 `### Task` 小节含「职责：」 |
| 风险清单表格 | 「风险清单」章节存在含「触发条件」「缓解」的表头行 |
| 节点文本预算 | mermaid 围栏内剥离边标签后，每个带引号节点文本 `<br/>` 计数 +1 ≤ 3 |

**人工断言**：

- 出口枚举完整性：逐份对照 §1 预埋的 3 种结局清点。
- 一图一主题：人工判定图的边界划分。
- 内容质量：人工读全部 10 份的决策论证、排除依据、代价段，按「是否出现不可判真伪的论证」「候选是否稻草人」粗评。

**闸门脚本自身的红绿自证**（仪器先于结论）：五类断言各做一个定向变异（删字段 / 删速览表行 / 节点塞 4 行 / 删职责句 / 风险表格改散文），逐一变红（exit 1）后还原变绿（exit 0）。自证过程抓出并修复闸门两个自身缺陷：风险章节断言原先在 END 处判 `inrisk`，章节结束即清零、永假——挪到章节边界；样本把字段写成 `**定位**：`（冒号在加粗外）时被误判缺字段——匹配前归一化剥离加粗标记。

**判定标准**：不以单份优劣下结论，以分布判定——实验组收敛（同形）而对照组发散（多种形状）即槽位有约束力；两组同好同坏即槽位无效，回炉。

## 6. 结论

1. **结构槽位有约束力**：实验组五份收敛同一形状、零方差；对照组五份五种形状。按方差判据 GREEN 达成。
2. **完整性类本次未分化**：出口枚举两组全对。出口表漏行是大规模多功能文档的失效类，小样本测不出区分——该类的兜底是独立审读层。三层分工据此确认：闸门管结构存在性、模板管形状一致性、审读管语义完整性。
3. **阴性结果（重要）**：对照组内容质量不差；新模板的形状收益不以论证质量为代价。

## 7. 边界与后续

- n=5/臂是微测规模，不是 AGENTS.md 要求的正式评测；正式 superpowers-evals A/B 列为可选后续。
- 单模型家族采样，跨 harness/模型方差未测。
- 小任务不触发完整性失效类，该类未获得区分证据；plan-template 臂（职责句/流程图槽位/分组）未做行为微测，由结构闸门与设计臂外推覆盖。
