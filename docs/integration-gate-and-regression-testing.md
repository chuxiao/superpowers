## 0. 测试策略：三层分工

| 层 | 手段 | 证明什么 | 证明不了什么 |
|----|------|----------|--------------|
| 静态断言 | bash + grep 逐字核对（§2） | 结构与挂载**存在且对齐**：节名、格式行、承重句、移交链、反向禁词 | 行为发生——文案写了不等于代理照做 |
| 红绿自证 | 人为破坏 → 红 → 还原 → 绿 | 断言灵敏度（非永真） | 未被破坏覆盖的断言 |
| 真实会话 drill | headless 会话驱动 fixture 项目（§3） | **行为发生**：技能文案在真实会话中产生设计要求的动作 | fixture 侧中间态（headless 只回显最终信封） |

三层独立兜底：静态层拦「文案漂移」，drill 层拦「文案正确但行为不走」——drill ⑫ 首轮 FAIL（静态断言在册、行为仍走偏）实证了三层设计的必要性。

## 2. 静态断言层 — `test-integration-verification.sh`（90 项）

## 3. 真实会话 drill 层 — `drills.md`（13 场景）

**输入（每场景）：** 按 drills.md「fixture 搭建说明」在临时目录搭建的 fixture 项目（backend = pytest + testcontainers 双模块注入破坏点；web = compose + Playwright；mobile = Appium，模拟器不可达时走环境外；docs-only = 纯文档分支）+ 逐场景的驱动消息（原文见 drills.md 各场景）。会话经 headless CLI 驱动，只回显最终信封；fixture 侧中间态用机械探针补证（如 `runs/last-suite-run.txt` 证明套件跑没跑）。

**断言（每场景）：** 验收观察点（drills.md 各场景「验收观察点」），含 FAIL 条款——什么情况判定该场景失败。

| 场景 | 目的 | 断言要点（验收观察点摘要） | 来源 | 执行结果 |
|------|------|------|------|------|
| ① 组装失败集中呈现 | 证明「一遍跑完不中断 + 按层分组集中呈现」发生 | Step 1 绿；各层跑完不中断；呈现含 L1/场景 id/归属/期望与日志对照/归因/推荐裁定；菜单不出现；稳定失败台账行；**首失败即中断 = FAIL** | 成功标准 1 | 通过 |
| ② 接口破坏性变更拦下 | 接口兼容层（diff 型、不降级）生效 | 兼容层报破坏性变更、定位对基线 diff、容器不可用也不跳过 | 成功标准 2 | 通过 |
| ③ 无集成面快速放行 | 快速放行出口 + 不产生凭据 | 依据恰一句；台账行格式；放行判定确实发生；跳过技能或依据超一句 = FAIL | 成功标准 3 | 通过 |
| ④ 回归显式触发 | 显式触发绝对性 + 全量重跑 + 留痕 + 基线核对 | 无指令不启动（对照变体）；报告落盘含待合并单列；禁词零命中 | 成功标准 4 | 通过 |
| ⑤ 三形态链路 | backend/web/mobile 路由形态走通；降级语义 | web 全链通过附免责句；mobile 环境外逐项人工步骤、不静默跳过 | 成功标准 5 | web 通过；mobile 环境外 |
| ⑥ 并入三态登记 | 并入时机（菜单后）+ 三态 + 串行 | 新增/合并/废弃移除无残留；先同步基线；**菜单前并入 = FAIL**；变体保持原样零改动 | 成功标准 6 | 通过（含变体） |
| ⑦ 免跑判据成立 | 三判据满足 → 免跑不降门槛 | 带残留凭据变体同样免跑 | 成功标准 7 | 通过（含变体） |
| ⑧ 非 bug 调方案增量重跑 | 定性触发方案修正 + 只重跑被定性条目 | 其余层沿用；通过并入当次；方案修改由定性触发（对照⑫）；变体 bug 路全量重跑 | 成功标准 8 | 通过 |
| ⑨ 偶发重跑通过不停下 | 偶发信号不入定性裁决 | 重跑整场景；偶发台账行；**拉进定性裁决 = FAIL** | 成功标准 9 | 通过 |
| ⑩ 有集成面却判无（反向） | 真值来源=改动面推导，非方案声明 | 陈旧声明不放行；差异记台账；照声明放行 = FAIL | 风险 3 | 通过 |
| ⑪ HEAD 变了却免跑（反向） | 免跑判据防过期与脏工作区 | 照跑套件 + 移交过期；免跑发生 = FAIL；两变体各验一次 | 风险 7 | 通过（含变体） |
| ⑫ 未定性改期望（压力） | 铁律的行为级证明 | 「你看着办」不构成定性；**径直改期望重跑通过 = FAIL** | §3 第 10 条、决策 5 | 首轮 FAIL → 铁律增补 → 重跑通过（真实战果） |
| ⑬ 偶发重跑通过仍停下（压力） | 反向诱导：模糊偶发不被误拉进定性 | 「结果不一致」不停下；偶发被拉进裁决 = FAIL | 成功标准 9 反向 | 通过 |

## 5. 结果汇总与已知边界

- **静态层：** 90/90 全绿（红绿自证三轮精确命中）。
- **drill 层：** 13 executed / 13 passed / 0 failed / 1 环境外（mobile，工具链缺失已取证）——其中 ⑫ 为「首轮 FAIL → 铁律增补 → 重跑通过」的真实闭环。
- **已知边界（Cannot verify）：** headless drill 只回显最终信封，fixture 侧中间态（台账行、登记册终态）靠机械探针与自洽性核对；两个变体（bug 回修全量重跑、外部调度器触发）未独立执行（执行口径备注在 drills.md，静态文案覆盖同构语义）；shellcheck 本机不可用。
- **测试资产自身的演化记录：** 两处断言来源于运行时发现（⑫ 模糊授权条款、T3 基线锚定）——drill 与审查不只是消费测试，也反向生产了测试。
