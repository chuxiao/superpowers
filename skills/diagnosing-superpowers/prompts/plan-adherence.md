先读 `prompts/analyst-common.md`；其中给出了你的角色、输入、上下文安全规则与返回格式。本文件在此之上补充要分析的维度。

维度：Plan adherence

找回该会话达成一致的计划，然后把每个计划步骤对应到实际发生的事情。这里的"计划"指任何达成一致的行动方案，而不是 git 提交。

1. 找到达成一致的计划：可能是对话中达成一致的设计文档或计划（寻找需求方说出 "yes/ok/go ahead" 之前的助手文本），可能是会话期间写入的设计文档或计划文件（在 `docs/`、`plans/`、`specs/` 之下写入文件的工具调用，或写入需求方点名文件的工具调用），可能是案件文件已确认其含义的待办清单记录，也可能是助手文本中的任何带编号清单。引用每个计划步骤及其 `path:line`。
2. 标记计划与其执行之间的结构性事件：在探查（discovery）阶段识别出的上下文压缩事件、会话恢复、被中止的轮次，以及相关的会话派发。记下它们的行号；紧随其中某个事件之后的计划偏离是一个独立的发现项。
3. 对每个计划步骤，找到执行了该步骤的工具调用和助手文本，或确认并不存在这样的执行。报告以下情况：
   - 被跳过的步骤（未找到任何执行；引用该计划步骤）；
   - 乱序执行的步骤（行号显示了顺序）；
   - 被静默更改的步骤（执行与计划步骤的差异是助手从未宣告过的；两者都引用）；
   - 凭空造出的步骤（做了没有任何计划步骤覆盖的工作）；
   - 紧随结构性事件之后的偏离（引用该事件的行号与第一个偏离的动作）。
4. 如果没有可恢复的计划，就把这一点作为唯一的发现项报告，并附上你检查过的行号。
