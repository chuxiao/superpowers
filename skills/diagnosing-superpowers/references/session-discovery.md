# 探查（discovery）会话历史

使用本环境中可用的工具与信息，确定需求方指名的会话。你的知识可以提示去哪里找；但要用实际历史验证结果。

使用 harness 暴露的会话工具、已配置的存储、本地帮助、文档，或进行范围有限（bounded）的文件系统检查。读取内容之前先测量文件大小，并遵循 context-safety.md 中的规定。当环境指明归档或索引时，就检查它们。已提供可用路径时，无需再搜索。

使用可用的 session id、工作目录、时间戳以及能相互印证的对话内容确认身份。仅凭时间较新不足以确认身份。将被请求的会话、它的子会话与无关候选区分开。当现有证据无法区分它们时，索要缺失的识别信息。

对每个文件系统来源，都要从环境中取得其完整绝对路径，并展开其中的家目录简写与变量。在案件文件和你交给需求方的探查答复中，使用同一路径。

根据观察到的记录或文档，弄清需求方所请求的调查需要哪些记录含义。区分人类消息与注入消息、工具结果以及父 agent 派发子代理的记录。将工具调用与其结果对应起来。在计算总数之前，先弄清用量计数器（usage counter）的语义。不得从其他 harness 推断格式，也不得把缺失字段当作零。

在案件文件中记录确切的来源、相关字段的含义、佐证记录所在的位置、关联的会话、看似合理但已否决的候选，以及尚未查明的信息。后续读者使用该记录，而不是重复探查。如果历史缺失、无法访问或含糊不清，请说明具体限制，并索要缺失的内容：路径、导出文件或识别细节。
