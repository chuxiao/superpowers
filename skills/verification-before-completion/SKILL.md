# 完成前验证

## 概述

**核心原则：** 证据先于声明，永远如此。

**违反这条规则的字面，就是违反这条规则的精神。**

## 铁律

```
没有全新验证证据，不得做出任何完成声明
```

如果你没有在当前这条消息里运行过验证命令，你就不能声称它通过。

## 闸门函数

```
在声称任何状态或表达满意之前：

1. 识别：什么命令能证明这个声明？
2. 运行：执行完整命令（全新、完整）
3. 读取：完整输出，检查退出码，统计失败数
4. 验证：输出是否证实该声明？
   - 若否：带证据陈述实际状态
   - 若是：做出声明时必须附带证据
5. 然后才可以：做出声明

跳过任何一步 = 在撒谎，不是在验证
```

## 常见失败

| 声明 | 需要 | 不充分 |
|-------|----------|----------------|
| 测试通过 | 测试命令输出：0 个失败 | 之前的运行、"应该能过" |
| linter 干净 | linter 输出：0 个错误 | 部分检查、外推 |
| 构建成功 | 构建命令：exit 0 | linter 通过、日志看起来不错 |
| bug 已修复 | 测试原始症状：通过 | 代码改了、就认定已修复 |
| 回归测试有效 | 红绿循环已验证 | 测试通过一次 |
| agent 已完成 | VCS diff 显示了变更 | agent 报告"成功" |
| 需求已满足 | 逐行核对清单 | 测试通过 |

## 危险信号——停下

- 使用"应该""大概""看起来"
- 在验证之前表达满意（"太好了！""完美！""搞定了！"等）
- 未经验证就准备提交/推送/发 PR
- 轻信 agent 的成功报告
- 依赖部分验证
- 想着"就这一次"
- 已经疲惫、只想赶紧收工
- **未运行验证，却用任何措辞暗示成功**

## 合理化借口防范

| 借口 | 现实 |
|--------|---------|
| "现在应该能行了" | 去运行验证 |
| "我很有信心" | 信心 ≠ 证据 |
| "就这一次" | 没有例外 |
| "linter 通过了" | linter ≠ 编译器 |
| "agent 说成功了" | 独立验证 |
| "我累了" | 疲惫 ≠ 借口 |
| "部分检查就够了" | 部分证明不了任何东西 |
| "换个措辞规则就不适用了" | 精神高于字面 |

## 关键模式

**测试：**
```
✅ [运行测试命令] [看到：34/34 通过] "所有测试通过"
❌ "现在应该能过了" / "看起来没问题"
```

**回归测试（TDD 红绿）：**
```
✅ 编写 → 运行（通过）→ 撤销修复 → 运行（必须失败）→ 恢复 → 运行（通过）
❌ "我写了一个回归测试"（未经红绿验证）
```

**构建：**
```
✅ [运行构建] [看到：exit 0] "构建通过"
❌ "linter 通过了"（linter 不检查编译）
```

**需求：**
```
✅ 重读计划 → 创建清单 → 逐项验证 → 报告缺口或完成
❌ "测试通过，阶段完成"
```

**agent 委派：**
```
✅ agent 报告成功 → 检查 VCS diff → 验证变更 → 报告实际状态
❌ 轻信 agent 报告
```

## 何时应用

**始终在以下操作之前：**
- 任何形式成功/完成声明的变体表述
- 任何满意的表达
- 任何关于工作状态的正面陈述
- 提交、创建 PR、任务完成
- 转向下一个任务
- 委派给 agent

**规则适用于：**
- 精确措辞
- 转述与同义词
- 对成功的暗示
- 任何暗示完成/正确的沟通
