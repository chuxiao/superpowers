# App 路由

本文件是 superpowers:integration-verification 的形态参考（手机 App 形态），由 Step 2 分层验证按形态路由加载。单测层不经本文件——由 Step 1 全量测试套件覆盖；接口兼容层不依赖运行环境，不随运行层降级。iOS 不在本路由（后置决策）：iOS 相关层以「环境外验证项」移交需求方。

## 默认执行器

| 层 | 默认执行器 |
|---|---|
| 集成层 L1 | 形态默认无执行器——App 是黑盒交付物，组装验证按项目声明执行；App 项目含独立后端模块时该部分走后端路由；声明缺失时标「未声明」 |
| 接口兼容层 | diff 型检查：按项目声明的接口规范对照基线跑破坏性变更检测（推荐规范 diff 工具，工具由项目安装）；未声明时标「未声明」 |
| 可运行层 L2 | 构建产物安装进 Android 模拟器、启动至首屏 + 健康判定（有界超时内可观测即通过） |
| 端到端层 L3 | Appium 场景驱动模拟器走冒烟集关键路径 |

Android 单模拟器起步，不做设备矩阵。

## 环境拉起

模拟器启动配置按下列清单推导（清单式指引，不是某个项目的配置）：

- 系统镜像：版本与项目声明一致；单实例冷启动。
- 就绪判定：`adb wait-for-device` + boot completed 标志，有界超时——模拟器启动慢是常态，不是失败。
- Appium server：项目侧启动，capabilities 指向本次构建产物——不装缓存的旧包。
- 场景间前置：卸载重装应用或等价清理，保证前置状态干净；模拟器实例按验证会话回收。

## 前置检查

各层执行前机械检查；技能内不安装任何工具，工具属于被验证的项目：

| 检查项 | 判定 | 缺失处置 |
|---|---|---|
| Android 工具链 | `adb`、`emulator` 可用且模拟器可达 | 可运行层与端到端层降级，剩余层级以「环境外验证项」移交需求方，逐项写明人工验证步骤 |
| Appium | 在项目依赖中且 server 可启动 | 移交需求方（环境外验证项） |
| iOS 工具链 | 不在本路由 | 相关层以「环境外验证项」移交需求方 |

## 失败重试与截图诊断

移动端天然 flaky，误报稀释验证公信力——对策从第一天设计进场景资产：

- 每个失败场景自动重跑一次（重跑整个场景，不是失败步骤）：重跑通过记偶发（台账记稳定性信号），不阻塞；重跑仍失败为稳定失败，收集至集中报告，不中断后续场景。
- 截图诊断每场景必配：失败时采集截图 + UI 层级（source）+ 设备与服务端日志——无证据采集物的稳定失败做不了证据对照，方案缺采集物本身记为方案缺口。
- 稳定失败集中呈现后由需求方定性裁决；定性 bug 且需求方裁定暂不修复的，场景在登记册标「已知不修」——回归单列呈现、不计为失败，直至指示修复或废弃。

❌「步骤级重试掩盖 flaky」　✅「整场景重跑一次，截图留证再定性」

## 资产化标准

进门禁的必须是确定性脚本资产，逐条核对：

- 进版本库、可重复执行、断言确定性。
- 确定性固定策略：等待一律用条件等待（元素出现、状态达成，有界超时）——固定 sleep 是 flaky 主源；测试数据与账号固定。
- 保真度声明：写明后端依赖是真实服务还是 stub、模拟器与真机差异对结论的影响——「通过」的含义随保真度明确。
- 副作用隔离：具破坏性外部副作用的操作（真实支付、推送、删数据）声明隔离手段（沙箱、测试账号、stub）；无隔离手段的标人工验证清单，不伪装自动化。
- 顺序依赖显式化：场景间依赖链显式声明，无依赖的标注可并行。
- 失败证据采集：每场景写明失败时的证据采集物（截图、source、日志范围）。
- 并入登记册前对照既有场景查重，重叠场景标注预期合并。

## 声明覆盖

项目声明（`docs/superpowers/verification/environment.md`）可覆盖执行器选择：项目已用其他方案（如 Detox、Maestro 等已建成的移动测试栈）时，各层写实际入口命令与环境要求即可覆盖默认执行器。覆盖后方案结构与资产化标准不变——分层、一遍跑完、前置检查、失败重试与截图诊断、资产化标准与移交语义全部沿用，只换执行器本身。

本文件是默认方案，项目声明可覆盖执行器选择；覆盖后方案结构与资产化标准不变。
