# Web 路由

本文件是 superpowers:integration-verification 的形态参考（Web 应用形态；Electron/Tauri 桌面应用同走本路由），由 Step 2 分层验证按形态路由加载。单测层不经本文件——由 Step 1 全量测试套件覆盖；接口兼容层不依赖运行环境，不随运行层降级。

## 默认执行器

| 层 | 默认执行器 |
|---|---|
| 集成层 L1 | docker-compose 栈内真实服务协作下验证跨模块组装（API 级脚本化调用断言） |
| 接口兼容层 | diff 型检查：按项目声明的接口规范对照基线跑破坏性变更检测（推荐规范 diff 工具，工具由项目安装）；未声明时标「未声明」 |
| 可运行层 L2 | 生产构建产物在栈内启动 + 健康检查（有界超时内可观测即通过） |
| 端到端层 L3 | Playwright 场景驱动真实浏览器走冒烟集关键路径 |

❌「mock 服务器上的『端到端』」　✅「栈内真实服务 + 真实浏览器」

## 环境拉起

栈定义进版本库，本身是资产。compose 栈应包含哪些服务，按集成面声明对照下述清单推导（本文件是形态通用方案，不含任何具体项目的栈内容）：

- 应用服务：构建产物 + 启动命令 + 健康检查定义。
- 中间件服务：数据库、缓存、消息中间件等被依赖者，逐项对应集成面声明的组装点，缺一不可、多一不必要。
- 数据初始化：一次性种子机制；每场景自带清理，防全量重跑的跨场景状态污染。
- 依赖与就绪：服务间启动顺序显式（依赖顺序 + 健康条件），栈就绪判定有界超时。

执行骨架：栈起（`up --wait` 等价）→ 各层一遍跑完 → 栈销毁（`down` 等价）；每次验证一套栈，用后销毁。Playwright 以 headless 模式驱动浏览器，场景入口指向栈内应用。

## 前置检查

各层执行前机械检查；技能内不安装任何工具，工具属于被验证的项目：

| 检查项 | 判定 | 缺失处置 |
|---|---|---|
| 容器运行时 | `docker compose version`（或等价命令）成功 | 栈承载层降级，剩余层级以「环境外验证项」移交需求方，逐项写明人工验证步骤 |
| Playwright 与浏览器 | 在项目依赖中，浏览器二进制就绪 | 移交需求方（环境外验证项） |
| 接口兼容层工具 | 按项目声明定位 | 未声明时该层标「未声明」，不阻塞 |

## 开发期探索

交互式浏览器调试工具（如浏览器调试类 MCP）只活在开发期：确认操作路径、复现边界场景。它们不进回归与门禁——交互式操作每次依赖现场探索，无沉淀、断言靠目测、token 成本高且不可并行。探索产物必须固化为脚本资产（Playwright 场景进版本库、断言确定性）方能进门禁；探索结论本身永不构成验证通过。

## 资产化标准

进门禁的必须是确定性脚本资产，逐条核对：

- 进版本库、可重复执行、断言确定性。
- 确定性固定策略：期望不依赖真实时钟、随机数、外部实时数据；等待一律用条件等待（自动等待、显式 expect 条件）——固定 sleep 是偶发失败的稳定来源。
- 保真度声明：写明栈内哪些是真实服务、哪些是 stub（第三方支付、邮件、外部 API）——「通过」的含义随保真度明确。
- 副作用隔离：具破坏性外部副作用的操作声明隔离手段（沙箱、测试账号、stub）；无隔离手段的标人工验证清单，不伪装自动化。
- 场景自包含：每场景前置写明搭建方式或数据来源、清理自带、独立可运行、并行安全（无固定端口、固定容器名、共享临时路径等全局资源标识依赖）、顺序编排只存在于场景内操作步骤。
- 失败证据采集：每场景写明失败时的证据采集物（截图、trace、页面快照、应用日志范围）。
- 并入登记册前对照既有场景查重，重叠场景标注预期合并。

## 声明覆盖

项目声明（`docs/superpowers/verification/environment.md`）可覆盖执行器选择：项目已用其他方案（如已用 Cypress 的 Web 项目声明 Cypress 即可）时，各层写实际入口命令与环境要求即可覆盖默认执行器。覆盖后方案结构与资产化标准不变——分层、一遍跑完、前置检查、资产化标准与移交语义全部沿用，只换执行器本身。

本文件是默认方案，项目声明可覆盖执行器选择；覆盖后方案结构与资产化标准不变。
