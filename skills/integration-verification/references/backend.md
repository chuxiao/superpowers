# 后端路由

本文件是 superpowers:integration-verification 的形态参考（后端服务形态），由 Step 2 分层验证按形态路由加载。单测层不经本文件——由 Step 1 全量测试套件覆盖；接口兼容层不依赖运行环境，不随运行层降级。

## 默认执行器

| 层 | 默认执行器 |
|---|---|
| 集成层 L1 | pytest / Jest 用例 + testcontainers：真实数据库/中间件协作下验证跨模块组装 |
| 接口兼容层 | diff 型检查：按项目声明的接口规范对照基线跑破坏性变更检测（推荐规范 diff 工具，工具由项目安装）；未声明时标「未声明」 |
| 可运行层 L2 | 构建产物按项目声明入口本地启动 + 健康检查（有界超时内可观测即通过） |
| 端到端层 L3 | 冒烟集关键路径：脚本化请求序列对运行中的产物断言端到端行为 |

❌「mock 掉数据库的集成测试」　✅「一次性真实容器内验证组装成立」

## 环境拉起

集成层每次测试运行拉起一套一次性真实容器，用后销毁。容器依赖清单按需求级验证方案的集成面声明推导：

- 被测模块依赖的数据库、缓存、消息中间件——集成面声明的每个组装点都有对应依赖，缺一不可；方案未涉及的不起。
- 容器生命周期由测试资产自身管理（testcontainers 在用例代码内声明、随测试销毁），不留长期共享容器——共享状态是跨场景污染与偶发失败的稳定来源。
- 每场景自带数据清理（种子与清理是资产的一部分），防全量重跑的跨场景状态污染。
- 可运行层不起容器：构建产物按项目声明启动，健康检查按项目声明判定。

## 前置检查

各层执行前机械检查；技能内不安装任何工具，工具属于被验证的项目：

| 检查项 | 判定 | 缺失处置 |
|---|---|---|
| 容器运行时 | `docker info`（或等价命令）成功 | 集成层降级，剩余层级以「环境外验证项」移交需求方，逐项写明人工验证步骤 |
| pytest / Jest | 在项目依赖声明中且可执行 | 移交需求方（环境外验证项） |
| 接口兼容层工具 | 按项目声明定位 | 未声明时该层标「未声明」，不阻塞 |

工具或环境缺失统一走环境受限降级（见 SKILL.md）：降级到环境可支撑的最深层级，不代装依赖。

## 资产化标准

进门禁的必须是确定性脚本资产，逐条核对：

- 进版本库、可重复执行、断言确定性。
- 确定性固定策略：期望不依赖真实时钟、随机数、外部实时数据；确需依赖时写固定策略（固定种子、固定数据集、固定时钟）。
- 保真度声明：写明哪些依赖是真实容器、哪些是 stub——「通过」的含义随保真度明确。
- 副作用隔离：具破坏性外部副作用的操作（真实支付、邮件、删数据）声明隔离手段（沙箱、测试账号、stub）；无隔离手段的标人工验证清单，不伪装自动化。
- 顺序依赖显式化：场景间依赖链显式声明，无依赖的标注可并行。
- 失败证据采集：每场景写明失败时的证据采集物（应用日志范围、容器日志导出）。
- 并入登记册前对照既有场景查重，重叠场景标注预期合并。

## 声明覆盖

项目声明（`docs/verification/environment.md`）可覆盖执行器选择：项目已用其他方案（自托管容器脚本、go test + dockertest 等）时，各层写实际入口命令与环境要求即可覆盖默认执行器。覆盖后方案结构与资产化标准不变——分层、一遍跑完、前置检查、资产化标准与移交语义全部沿用，只换执行器本身。

本文件是默认方案，项目声明可覆盖执行器选择；覆盖后方案结构与资产化标准不变。
