# Claude Code 工具说明

Claude Code 是基准 harness：技能使用的就是它的词汇——派发子代理用 `Agent`，待办用 `Task`，调用技能用 `Skill`。本文只讲一个特例：在 Claude Code 上，有一种比技能默认形态更省钱的计划执行方式（见下一节）。用不用，由需求方决定；无论用不用，技能要求的任何内容都不改变。

## 子代理驱动开发的更省钱编排

在 superpowers:subagent-driven-development 的一次运行中，控制者会话是成本最高的参与者——一个会话或子代理上下文，它要读取每一份派发结果和每一份报告，而且通常运行在会话所能用的最强模型上。Claude Code 支持嵌套子代理（默认在主会话之下三层；`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 可调整该层数），所以整个循环可以下沉一层运行。

当需求方提出要求——或已表示用会话模型做协调代价过高——就仅派发一个编排器子代理：使用中档模型，附上计划路径并下达指令，要求它端到端使用 superpowers:subagent-driven-development。编排器按该技能的 Model Selection（模型选择）一节派发自己的实施者与审查者；工作区和台账都存放在磁盘上，所以多出的这一层不会丢失任何内容。它的最终消息必须逐字带上 "Rulings I made"（我做出的裁决）清单——这份清单是各项决定传达给需求方的途径，你要转达它，而不是总结它。

只对整个计划这样做。把单个任务的派发再嵌套一层毫无收益，只会多出一个参与者、多一份开销。
