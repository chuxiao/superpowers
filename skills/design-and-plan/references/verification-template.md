# 验证方案模板

> 读者假设：需求方（审核完备性）与验证执行者（按场景执行）；懂软件工程，不熟悉产生本文档的对话。
>
> 本文档回答：怎么证明做成的东西就是 design.md 承诺的东西——集成面有哪些、每个面拿什么场景钉住、通过判据是什么、由谁与怎么执行、失败时留什么证据。

## 产出判据

计划存在跨任务组装点或触及外部接口 → 产出 verification.md，与 design.md、plan.md 同目录（`docs/superpowers/specs/<date-feature>/verification.md`）。

纯单模块无接口 → 不产出，plan.md 骨架不变。判定不产出时，把推导依据写进计划：改动面清单 → 无组装点、无外部接口、无运行边界的推导链；不写依据的无方案不合法。

## 章节骨架

产出文档标题 `# <项目> 验证方案`，文首为上方读者声明引块；其后按序成文：

1 集成面声明 / 2 场景清单 / 3 通过判据 / 4 验证环境 / 5 执行手段 / 6 产出物 / 固定节：可观测缝清单；章末附修复闭环轮次上限 N（默认 3，需求方可改）

- 六节按需求方审核动线排序：集成面声明与双向映射表在前，完备性当场可查。
- 场景出处统一记法见「场景清单」节：`§N` 指 design.md、`Task N` 指 plan.md、`I-N` 指 implementation.md。
- 场景间无依赖、可并行调度：场景自包含五要素判据（前置写明、清理自带、独立可运行、并行安全、顺序编排只在场景内）见「质量判据与自查」节。

## 1. 集成面声明

跨任务组装点与外部接口逐个列出；随后紧跟集成面与场景清单的双向映射表——有面无场景是缺口、有场景无面是跑偏，完备性当场可查。

## 2. 场景清单

主路径、高风险分支、跨模块契约点各有至少一条场景；每场景写前置状态、操作步骤、期望结果、清理；期望以表格呈现并附出处标注列——无出处不得入方案。

**场景出处约定：** 出处标注使用统一记法——`§N` 指 design.md 第 N 章；`Task N` 指 plan.md 的对应任务；`I-N` 指 implementation.md 的对应接口 / 数据章节。

## 3. 通过判据

每条场景的期望结果可判真伪。

## 4. 验证环境

各层入口命令与环境要求。

## 5. 执行手段

资产化场景进登记册，或人工验证清单——人工条目明确标注，不伪装自动化。

**分层自动化策略：** 机器可操作步骤（启动、改文件、备份恢复、辅助功能 API 模拟点击）由驱动脚本执行；断言优先用「可观测缝」（环境变量、调试日志、系统状态可查询接口）；真人工只剩：权限弹窗类（一次性授权点击）、不可模拟的拒绝路径、会话级验证（注销重登）——逐条诚实标注，不伪装自动化。

## 6. 产出物

失败时的证据采集物（截图、trace、日志范围）。

## 可观测缝清单

为验证而设的环境变量 / 日志点 / 状态查询逐个列出，每条注明：用途（钉住哪个场景的哪个断言）与对正常运行零影响的论证。

## 质量判据与自查

- 粒度与可操作性判据逐场景自查：一个场景一个行为目标、期望为可观测的具体结果、每步为明确动作。
- 内容要求六项逐项落实——确定性固定策略、保真度声明、副作用隔离、场景自包含、既有登记册查重、失败证据采集。
- 场景自包含判据逐场景自查——前置写明搭建方式或数据来源、清理自带、独立可运行、并行安全（无固定端口、固定容器名、共享临时路径等全局资源标识依赖）、顺序编排只存在于场景内操作步骤。
- 跨场景承接即方案缺口，按序三出路消化：先造数自备前置（优先）；造数不可达 → 合并为路径级场景；仍不可达 → 人工验证清单（既有机制，不伪装自动化）。

## 修复闭环

章末附修复闭环轮次上限 N（默认 3，需求方可改）与人工验证清单标注——写不出确定性步骤的场景标人工验证清单，不伪装自动化，与执行手段的人工条目一致。
