# 验证方案模板

> 读者假设：需求方（审核完备性）与验证执行者（按场景执行）；懂软件工程，不熟悉产生本文档的对话。
>
> 本文档回答：怎么证明做成的东西就是 design.md 承诺的东西——集成面有哪些、每个面拿什么场景钉住、通过判据是什么、由谁与怎么执行、失败时留什么证据。

产出判据（何时产出本文件）见 `plan-template.md`「验证方案文件」段：计划存在跨任务组装点或触及外部接口时产出，与 design.md、plan.md 同目录（`docs/superpowers/specs/<date-feature>/verification.md`）；判定产出后按本模板成文。

## 章节骨架

按需求方审核动线排序，六节固定：集成面声明与双向映射表在前（完备性当场可查），随后场景清单、通过判据、验证环境、执行手段、产出物。另含两个固定节：可观测缝清单（执行手段的支撑）与引擎 + 场景数据分离（驱动脚本的架构约定）。

## 1. 集成面声明

跨任务组装点与外部接口逐个列出；随后紧跟集成面与场景清单的双向映射表——有面无场景是缺口、有场景无面是跑偏，完备性当场可查。

## 2. 场景清单

主路径、高风险分支、跨模块契约点各有至少一条场景；每场景写前置状态、操作步骤、期望结果、清理；期望以表格呈现并附出处标注列——无出处不得入方案。

**场景出处约定：** 出处标注使用统一记法——`§N` 指 design.md 第 N 章；`Task N` 指 plan.md 的对应任务；`I-N` 指 implementation.md 的对应接口 / 数据章节。

## 3. 通过判据

每条场景的期望结果可判真伪。

## 4. 验证环境

各层入口命令与环境要求。

## 5. 执行手段

资产化场景进登记册由引擎执行，或人工验证清单——人工条目明确标注，不伪装自动化。

**分层自动化策略：** 机器可操作步骤（启动、改文件、备份恢复、辅助功能 API 模拟点击）由驱动脚本执行；断言优先用「可观测缝」（环境变量、调试日志、系统状态可查询接口）；真人工只剩：权限弹窗类（一次性授权点击）、不可模拟的拒绝路径、会话级验证（注销重登）——逐条诚实标注，不伪装自动化。

## 6. 产出物

失败时的证据采集物（截图、trace、日志范围）。

## 可观测缝清单

为验证而设的环境变量 / 日志点 / 状态查询逐个列出，每条注明：用途（钉住哪个场景的哪个断言）与对正常运行零影响的论证。

## 引擎 + 场景数据分离

驱动脚本与具体场景耦合（每 feature 一份脚本代码）时，并入登记册会面临代码级合并，替换删除无解、且随 specs 归档冻结成死物。因此驱动脚本一律拆为引擎 + 场景数据：

- **引擎：** 项目级通用执行器（如 `scripts/verify-engine`），只认场景 DSL，不含具体场景；一次编写、极少演进，不随 feature 归档。
- **场景数据：** 结构化条目活在 verification.md / 登记册，字段含 `id`（登记册合并键，全局唯一）、`schema`（DSL 版本）、`title`、`kind`（auto / semi / human）、`steps`（引擎内置操作原语：backup/launch/quit、file-check、log-grep、ax-click/ax-read/ax-type、run-command、sleep，按需增原语）、`assertions`（机器断言）、`human-observe`（人工观察点，引擎收集后统一呈报）、`cleanup`。
- **生命周期：** finish 阶段并入登记册 = 数据条目合并，引擎不动；场景替换 / 删除 = 改条目 + decisions.md 记录；specs 归档冻结的是快照，登记册持现行有效数据，引擎只读登记册；regression-sweep 由引擎解释执行登记册并汇总 PASS/FAIL。
- **冲突与漂移：** 同 id 不同期望 → finishing 人工环节裁决并记 decisions.md；UI 变更导致 ax 断言失效 → 改场景数据（与维护测试代码同理），回归失败即漂移信号。
- **起步策略：** 原语从当前场景所需最小集起步，随新需求扩展；kind=human 的场景引擎只收集观察点、不执行。

## 质量判据与自查

- 粒度与可操作性判据逐场景自查：一个场景一个行为目标、期望为可观测的具体结果、每步为明确动作。
- 内容要求六项逐项落实——确定性固定策略、保真度声明、副作用隔离、场景自包含、既有登记册查重、失败证据采集。
- 场景自包含判据逐场景自查——前置写明搭建方式或数据来源、清理自带、独立可运行、并行安全（无固定端口、固定容器名、共享临时路径等全局资源标识依赖）、顺序编排只存在于场景内操作步骤。
- 跨场景承接即方案缺口，按序三出路消化：先造数自备前置（优先）；造数不可达 → 合并为路径级场景；仍不可达 → 人工验证清单（既有机制，不伪装自动化）。

## 修复闭环

章末附修复闭环轮次上限 N（默认 3，需求方可改）与人工验证清单标注——写不出确定性步骤的场景标人工验证清单，不伪装自动化，与执行手段的人工条目一致。
