# 实现设计的流程与规则

> 写 implementation.md 之前先读本文档。A 组是做设计时的判断力（经典工程原则），B 组来自真实失败，C 组是成文时的动作规则——统一审读按这些规则的可判定信号核对 implementation.md。

## A 组：架构设计原则

1. **关注点分离**——业务逻辑、展示、持久化、配置各归其位；一个模块只回答一个问题。违反信号：改一个业务规则要同时碰展示层和存储层。
2. **高内聚、低耦合**——内聚的判据不是「功能相近」，而是「变化理由相同」：模块内部元素因同一个理由一起变化（单一职责的正面表述）。耦合的实测信号是改动放大：改一处要动 N 处，就是耦合过高。模块间走窄接口，不做大而全的「工具箱模块」。
3. **抽象与信息隐藏**——调用方依赖抽象而非实现。违反信号：接口签名暴露内部结构（返回内部对象）、要求调用方知道内部调用顺序——即泄漏抽象。一个接口一个角色，不让任何调用方被迫依赖它用不到的方法（接口隔离）。
4. **依赖单向、指向稳定**——被依赖者不知道依赖者；高层策略与低层细节都依赖抽象（依赖倒置）；循环依赖在结构设计章当场拆掉（拆接口 / 事件 / 回调），不是标注「以后处理」。
5. **最少知识**——只与直接协作方通信。违反信号：`a.b().c().d()` 链式深入他人的内部结构。
6. **组合优于继承**——继承层次超过两层即警惕，优先组合 + 接口注入；实现接口时遵守行为契约（里氏替换）：子类型必须能无惊地替换父类型的约定。
7. **消灭偶然复杂度**——区分必需复杂度（问题本身固有的）与偶然复杂度（方案选择引入的），后者是设计缺陷；简单方案能用就不上复杂方案。对「已知的变更方向」留缝（版本字段、错误码留段），不为想象中的需求建抽象（开闭原则与 YAGNI 的边界）。

## B 组：实证纪律

8. **接口是承诺，不是清单**——凡被「被谁依赖」引用的接口，签名、错误语义、示例结果的任何变更都是兼容性变更，须过确认门。
9. **先外部后内部**——外部契约（endpoint / CLI / 公共 API）先冻结，内部接口围绕它设计，不是反过来；实现细节不进接口章。
10. **失败路径与降级是一等公民**——每个外部依赖（网络 / 磁盘 / 进程 / 第三方）必须写明失败行为（超时、重试、降级、报错路径）；「正常路径走通」不等于设计完成。
11. **状态必须有唯一归属**——每个状态单一写点、单一事实来源；「谁拥有这个状态」答不出来就是设计缺口；共享状态必须写并发与一致性语义。
12. **数据是最大的承诺**——字段表没有示例值即臆写；外部格式转换逐字对照（转换是数据丢失高发地）；状态机穷举非法迁移，漏掉的迁移就是线上事故。
13. **平台能力约束必须实测后写**——禁写「应该可以」；构建工具链能力边界、自动化测试可用性，写进界面实现规格章之前必须实测验证。

## C 组：成文纪律

14. **六段式每段防一件事**——职责段防接口蔓延；参数表「约束与非法值」列防未定义行为；错误表防吞错误（「不会失败」也要写明为何不会）；示例段防「以为懂了」——写不出逐字示例的接口就是没想清；被谁依赖防死接口（无人依赖即删）。
15. **结构对齐任务**——模块边界就是 plan.md 的任务边界，结构含糊则拆分必返工。
16. **规模评估是预算不是散文**——量化数字（行数 / QPS / 体积）是「做不动」的早期报警；写不出数字的章说明设计没想透。
17. **流程链路必须锚定接口**——链路图标注 I-N 章节号，图与接口互相可追溯，防「图是图、码是码」。
18. **一致性优先于完备**——同一概念在全部章节用同一名字同一语义；同一业务规则只在一处实现——重复的规则必然漂移（DRY 的本义是知识的单一表示，不是文本不重复）。两章描述同一事物却说法不同，比缺一章更危险。
19. **三件分工边界**——design 管「是什么」（行为承诺），implementation 管「怎么存怎么算」（物理实现），plan 管「怎么切怎么验」（执行切分）；实现细节渗进 design、签名复制进 plan、结构依据留在 plan 不上收，三种越界都是返工之源。
20. **条件章裁剪纪律**——裁掉的章不留残留任务；保留的承诺（如纯 API 错误码契约）必须有实质内容，「本章不适用」不是裁剪。
21. **无锚引用禁令**——凡「已确认 / 已验证 / 已裁决」必须能指到仓库内文件或 decisions.md 条目，否则删掉断言或先落盘再引用。
