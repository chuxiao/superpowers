# 安全复审提示词模板（安全门限定复审）

在安全修复轮之后派发复审时使用此模板。复审者验证安全门审查的各发现项是否已得到解决，并检查修复 diff 有无新的安全问题。这不是一次全新的审查——安全门审查此前已经完成；本复审是该分支并入 main 前的最后一次审查。

**目的：** 验证安全门审查的每个发现项均已解决，且修复本身未引入新的安全问题。

```
Subagent (general-purpose):
  description: "安全门复审：验证安全修复轮"
  model: [MODEL — 必填：最强档。Model Selection 中限定范围重审的低档规则不适用于安全门复审：安全复审是合并前的判断型任务，依据为设计文档决策 6]
  prompt: |
    你正在复审安全门的修复轮。此前安全门审查产出了安全发现项；一名修复者已尝试修复它们。你的工作是对每个发现项给出判定，并检查修复 diff——除此之外别无其他。

    ## 待验证的发现项

    [FINDINGS]

    ## 修复

    阅读修复者的报告：
    [REPORT_FILE]

    **修复基点：** [FIX_BASE_SHA]（即安全门审查所看到的 head）
    **Head:** [HEAD_SHA]
    **Diff 文件：** [DIFF_FILE]

    diff 文件读一遍即可——它包含修复提交、一份 stat 摘要，以及带周围上下文的修复 diff。不要重新运行 git 命令。
    如果 diff 文件缺失，自行获取 diff：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 和
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    你在本次检出上的审查是只读的。不得以任何方式改动工作树、暂存区（index）、HEAD 或分支状态。

    ## 你不得派发子代理

    这场审查的全部工作都由你亲自完成。绝不派生子代理去审查 diff 的一部分，也绝不派生另一名审查者来提供第二意见。该流程已为这项工作安排了固定的审查次数；你再派生的审查者只是以同等成本把其中一次审查重做一遍，且其判定不会被采纳。如果 diff 大到让你觉得无法一遍完成，就自行分多遍审查，并在报告中说明。

    ## 范围

    你的范围是发现项列表和修复 diff。对每个发现项给出判定。检查修复 diff 中有无修复本身引入的新安全问题。绝不重新审查修复未触及的代码：完全位于修复 diff 之外的问题报告在 Out-of-Scope Observations 一节——不阻塞本流程，控制者会将其记入台账。本复审是该分支合并前的最后一次审查：没有任何后续审查会接手你在本节之外搁置的问题，判定与报告都要在本轮给全。

    ## 测试

    修复者已重新运行覆盖被修改代码的测试，并将结果写在报告文件中。将该报告视为未经证实的声明：确认报告写明了覆盖这些代码的测试并展示了其输出，并对照 diff 核验这些声明。不要为了确认其报告而重新运行测试套件。仅当阅读代码时产生了具体疑点、而现有测试结果回答不了它时，才运行测试——且届时只运行聚焦测试，绝不运行包级测试套件。

    ## 判定标准

    「已尝试」不算 ADDRESSED：发现项所指的具体缺陷必须已不复存在，判定附 file:line 证据。

    ## 输出格式

    你的最终消息就是报告本身：直接以第一项发现项的判定开头。每一行要么是一个判定、要么是带 file:line 的发现项、要么是你运行过的一项检查——不要开场白，也不要过程叙述。

    ### Finding Verdicts

    针对「待验证的发现项」一节中的每个发现项，按顺序给出：
    - **[finding one-liner]** — ADDRESSED | NOT ADDRESSED，并附 file:line 证据。

    ### New Security Issues in the Fix Diff

    修复本身破坏或引入的任何安全问题，标注严重度（Critical/Important/Minor）并附 file:line。若干净，写 "None"。本节只报告：不触发新的修复轮，处置由控制者按挂载规则进行。

    ### Out-of-Scope Observations

    你注意到的完全位于修复 diff 之外的问题（安全或非安全）。不阻塞本流程。若无，写 "None"。

    ### Verdict

    **Fix round:** [All findings addressed, no new Critical/Important security issues | Findings remain open]——列出仍未解决的发现项。
```

**占位符：**
- `[MODEL]` — 必填：最强档。Model Selection 中限定范围重审的低档规则不适用于安全门复审，依据为设计文档决策 6
- `[FINDINGS]` — 安全门审查的全部 Critical/Important 安全发现项，逐字复制，每条占一个列表项，逐项判定，无一跳过
- `[REPORT_FILE]` — 安全修复者的报告文件（修复报告与测试证据在其中；会话内执行时为台账中的安全修复行及其测试输出）
- `[FIX_BASE_SHA]` — 安全门审查所看到的 head
- `[HEAD_SHA]` — 当前提交
- `[DIFF_FILE]` — 控制者运行 `review-package` 生成并填入的路径

**复审者返回：** 各发现项的判定（ADDRESSED / NOT ADDRESSED）、修复 diff 中的新安全问题、范围外观察项，以及针对该轮的判定。
